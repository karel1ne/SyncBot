# SyncBot — Телеграм-бот для зеркалирования сообщений

Надежный Telegram userbot, написанный на Python 3.13 с использованием библиотеки [Kurigram](https://github.com/Kurimuzard/kurigram) (форк Pyrogram). Бот автоматически синхронизирует сообщения и медиа-группы между каналами, поддерживая обход ограничений на пересылку контента.

## Обзор возможностей

- **Автоматическое копирование:** Перенос сообщений из исходного канала в целевой в реальном времени.
- **Обход защиты контента:** Если в исходном канале запрещена пересылка (Content Protected), бот автоматически скачивает медиа и загружает его заново как новое сообщение.
- **Поддержка медиа-групп:** Корректная обработка альбомов (фото, видео) с сохранением подписей и форматирования.
- **Синхронизация истории:** При запуске бот проверяет последние пропущенные сообщения (до 100-200 штук), чтобы избежать пропусков во время простоя.
- **Сохранение состояния:** Использует `state.json` для отслеживания последнего обработанного сообщения и предотвращения дубликатов.

## Технологический стек

- **Python:** 3.13+
- **Telegram Library:** `kurigram` (современная альтернатива Pyrogram)
- **Dependency Management:** `uv`
- **Configuration:** `pydantic-settings` (поддержка YAML/ENV)
- **Logging:** `loguru`
- **Containerization:** Docker & Docker Compose

## Быстрый старт

### Предварительные условия

1. Получите `API_ID` и `API_HASH` на [my.telegram.org](https://my.telegram.org).
2. Узнайте ID исходного и целевого каналов (или их юзернеймы).
3. Установите [uv](https://github.com/astral-sh/uv) (рекомендуется для локального запуска).

### Настройка

Создайте файл `.env` на основе примера:

```env
API_ID=ваш_api_id
API_HASH=ваш_api_hash
SOURCE_CHANNEL=-100... или username
DEST_CHANNEL=-100... или username
# Необязательно:
SESSION_STRING=ваша_строка_сессии
```

### Получение SESSION_STRING

Если вы планируете запускать бота в Docker или на удаленном сервере, удобнее всего использовать `SESSION_STRING`. Для её получения:

1. Заполните `API_ID` и `API_HASH` в `.env`.
2. Запустите скрипт:
   ```bash
   uv run python get_session.py
   ```
3. Следуйте инструкциям в терминале. Полученную строку добавьте в `.env` как `SESSION_STRING`.

### Локальный запуск

1. **Установка зависимостей:**
   ```bash
   uv sync
   ```
2. **Запуск бота:**
   ```bash
   uv run python -m syncbot
   ```
   *Примечание: При первом запуске (если не указан `SESSION_STRING`) бот предложит авторизоваться через терминал. Это создаст файл `my_account.session`.*

### Запуск через Docker

```bash
docker compose up -d --build
```
*Для работы в Docker рекомендуется заранее получить `SESSION_STRING` или пробросить `my_account.session` в контейнер.*

## Разработка и тестирование

### Команды для разработки

- **Тестирование:** `uv run pytest`
- **Линтинг (Ruff):** `uv run ruff check src`
- **Форматирование:** `uv run ruff format src`
- **Проверка типов (Mypy):** `uv run mypy src`

### Структура проекта

- `src/syncbot/`: Основной код приложения.
    - `bot.py`: Главный класс бота и логика инициализации.
    - `logic.py`: Основная логика копирования сообщений и обхода ограничений.
    - `handlers.py`: Обработчики входящих событий Telegram.
    - `config.py`: Управление конфигурацией через Pydantic.
    - `state.py`: Работа с состоянием (JSON).
- `state.json`: Файл для хранения ID последнего обработанного сообщения.
- `my_account.session`: Файл сессии Telegram (не для коммита!).
- `get_session.py`: Скрипт для генерации `SESSION_STRING`.

## Лицензия

Этот проект предназначен для личного использования. Соблюдайте правила Telegram и авторские права при копировании контента.
